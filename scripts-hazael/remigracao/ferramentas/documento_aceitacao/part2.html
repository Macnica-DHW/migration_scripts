4. Page acceptance guidelines

Each guideline gives the criterion a page must meet (Pass when), how a reviewer checks it, the global2 setting that produces it, and where it comes from. Pictures show accepted and not accepted results wherever words alone could be read in more than one way. All measurements follow R7 (view mode, 1,400px page area).

Migration principle marks a guideline that follows from Section 2. From review marks a guideline that restates what Anion's review comments ask for. Proposed marks a measurement or a choice that we propose and ask you to confirm (Section 6).

A. Content

G1 Content matches the original GWI page Migration principle · question M1

Pass when
  • Every text block, image, link, table, video and download shown on the GWI page is on the global2 page, with the same words, and the blocks are in the same order.
  • Nothing that GWI does not show is added, except the differences listed below.
  • The page title and page description in the page properties are those of the GWI page.
  • On a page with tabs, each tab holds what the matching GWI tab holds.
Allowed differences
  • Changes that another guideline requires, with the words, images and links of each block unchanged: an image placed on the left of its text (G10) or beside it (G11), a video paired with its text (G12), heading levels (G5), end-of-page contact buttons shown through the Experience Fragment with the same labels and links (G14).
  • Empty lines that GWI uses only as spacing are removed. A GWI download box becomes a download button with GWI's label (G4). An in-page menu that only links to an event's website becomes a button with GWI's text and address.
  • Links decided in question M4.
  • Image and Title links open in the same tab: the author dialog of these components offers no open in a new tab option.
How to check
Open both pages (R1, R3) and read them block by block; open every tab on both (R4).
Basis
The migration principle (Section 2, P1). Anion's comments about content are listed in question A10, with the other comments that need a block named, so that each block can be compared with its GWI page.

G2 Links Migration principle

Pass when
  • Every link has the same destination as on GWI, except the links decided in question M4. Links to other Macnica Americas pages open the global2 page.
  • Every link opens without an error when clicked in view mode.
  • A link in a Text, Button or Text with Image opens in a new tab only where GWI opens it in a new tab.
  • No link is written with a full author address (https://author-…adobeaemcloud.com/…) or with editor.html, and none points to a GWI page (/content/macnicagwi) or to a file stored on GWI. While pages are reviewed on the author, internal links open on the author: that is expected.
Not counted
A link to a Macnica page that is outside this migration and not yet on global2: it is kept as on GWI.
How to check
Click each link in view mode and compare its destination with the same link on GWI.
In global2
The link field of Text, Title, Button, Image and Text with Image. Text, Button and Text with Image links have an open in a new tab option.
Basis
The migration principle (Section 2, P1): every link as on GWI, pointing to the global2 page.

G3 Images From review · limits proposed

Pass when
  • Every image loads, shows the whole picture (nothing cut off) and is stored in the global2 asset library (DAM), not on GWI.
  • An image is never shown wider than its file, except an image that fills the content width under G11 or an image in a row or grid under the next point, each enlarged at most 1.5 times its file width.
  • Images side by side in one row or grid have the same displayed width: each uses Size: Expand to Fit Width in equal Flex Container items. Where a file would have to be enlarged more than 1.5 times, the images are shown at their file widths, centred in equal columns. Heights match only when the files have the same proportions.
  • The alternative text is the GWI image's alternative text. Where GWI has none: as decided in question M3.
Not counted
Card List images, which the Card List always crops to a 2:1 frame (G16).
How to check
View mode. Right-click the image, Inspect: the browser shows its displayed size and the file's own size. In the author, the image's Alternative Text field, with Get alternative text from DAM unchecked so that the page's own text is used.
In global2
Image and Text with Image components. Images in a row: equal Flex Container items with the same Image settings. The Image style Size: Expand to Fit Width only where G11 applies.
Basis
Anion, 23 Sep: Images are bigger in size, no alignment (IBASE IB836, EC-7100; IEI AFL3-W19C-ULT5, FLEX AIoT Developer Kit Gen II, KINO-DH420).

B. Page structure

G5 Headings From review · levels in question A2

Pass when
  • The page has exactly one H1: the page title, at the top of the content.
  • A title that sits directly in a top-level section is an H2. A title inside a card, a Flex Container item or a tab panel under an H2, or a title that follows an H2 in the same section and introduces part of its content, is an H3; below that, H4. A tab-panel title is one level below the nearest heading above the tab bar. A section title stays an H2 when it sits in a Flex Container item beside a video (G12) or opens a Text with Image (question A3).
  • No level is skipped going down: H1 directly followed by H3 fails.
  • A section title is always a heading. A paragraph whose whole text is bold, stands on its own line and introduces the text below it is a title, and it is formatted as a heading.
  • No empty headings.
Not counted
Headings in the site header and footer (R5).
How to check
In the author: the heading level set on each Title component (a Title whose level was never set is an H1), and the paragraph format (Heading 2, Heading 3…) of headings typed inside Text or Text with Image. In view mode, right-click a title, Inspect: the tag shows its level (h1, h2…).
In global2
Title component (heading level H1 to H6); paragraph formats Heading 1 to Heading 6 in Text and Text with Image. Our reading of the review comment and the size of headings: question A2. A title placed beside an image: question A3.
Basis
Anion, 27 Sep: Subtitles should not be H1. Only main title should be H1. (MB991). Anion, 28 Sep: only main title should be h1/h2, remaining titles should not be h1 (Hitek pages, news items, IEI Embedded Systems, IBASE MB995, SiTime Clock Buffers, Japan Innovation Showcase, Contact download page, error page); Titles are kept as para (IBASE IB836); Title issue (EC-7100, AFL3-W19C-ULT5).

G6 Text formatting From review

Pass when
  • Body text uses the default paragraph format. No body text is enlarged or reduced with the Text Font Size styles (the size of titles: question A2).
  • Bold, italic and lists are as on GWI.
  • Lines that GWI shows with no blank space between them (an address, a phone and e-mail block) are one paragraph with line breaks. Lines that GWI separates with a blank space are separate paragraphs.
  • No empty paragraph between a title and its text, or between two paragraphs.
How to check
View mode, side by side with GWI. In the author's text editor, Shift+Enter makes a line break (lines 30px apart); Enter starts a new paragraph (a paragraph gap is added).
In global2
Text and Text with Image editors: paragraph format Paragraph; Shift+Enter for a line break.

G7 Page width and side padding Proposed · question A1

Pass when
  • Content uses the full window width; no section uses the fixed 1,000px column.
  • Every top-level section has the left and right padding decided in question A1. Recommended: 50px each side (Padding - Left/Right: Large), which leaves the content 1,300px wide in a 1,400px page area.
  • No text, image or table touches the window edge.
Not counted
Content inside the end-of-page contact Experience Fragment, which brings its own padding and starts 25px further in.
How to check
View mode: the text, images and tables of every section start and end at the chosen distance from the window edges (measure the content, not the grey band).
In global2
Container style Padding - Left/Right on each top-level section: Large 50px, Medium (the default) 25px, Small 15px, No Padding 0. Tab panels and containers nested inside a section use No Padding, so the section's padding applies once. The 1000px width style is not used.
Basis
Anion, 27 Sep: Need to give Padding Left/Right for all Altera, Anlog, microchip, on-semiconductor, sitime pages. Anion, 28 Sep: L/R Padding - should be large (Smart City & Mobility, Terasic Apollo S10 SOM, Transcend).

G8 Vertical spacing Proposed · numbers to confirm

Pass when
  • Title to the first line of its text, with no empty line between them: 45px or less when a Title component is followed by a Text; 70px or less when the text is in a Text with Image, either typed as its first line or placed below a Title component (the Text with Image adds 30px above itself, and the editor adds a paragraph gap after a heading).
  • Paragraph to paragraph: the standard paragraph gap only (30px between line boxes). No empty paragraphs used as spacers.
  • Block to next block, inside a section or between sections: 125px or less.
  • Above the end-of-page contact buttons: 150px or less, because about 90px of that space is part of the Experience Fragment itself.
  • Blocks never touch: at least 20px between an image, table or button and the next block.
  • Bottom of the tab labels to the first line of the tab's content: 60px or less (G15).
Not counted
The space below a form, which the form component sets.
How to check
R7, on the whole page in view mode. As a quick reference, lines of body text are 30px apart.
In global2
Vertical space comes from Container padding (Padding - Top/Bottom: Large 70px, Medium (the default) 50px, Small 30px, No Padding 0) plus the fixed spacing of each component (Title: H1 and H2 about 12px above and below, H3 20px below only; Table 20px; Text with Image 30px; Button 40px above it; List 55px; video 24px above it). There is no setting for the space between two components. Two default sections in a row leave 100px between their contents (50px + 50px); where a gap passes 125px, one of the two sections uses Small. An Image and a Button have no space below them: when another block follows, it starts in a new Container with Small.
Basis
Anion, 21 Sep: white space. Anion, 23 Sep: Spacing issues (IBASE MB995). Anion, 27 Sep: Spacing b/w section to section, Spacing issue. Anion, 28 Sep: Spacing in the content (Design Services, Broadcast & ProAV), Lots of spaces in page for images and content. (Luminous Comet A65), Padding issue for Features section (TQMLS1028A).

G9 Background bands Proposed · question A6

Pass when
  • The page title and the introduction (everything between the H1 and the first H2) are on white.
  • A grey band starts at an H2 and ends before the next white section or before the end-of-page buttons. It holds at least two blocks and is at least 200px tall, from its top grey edge to its bottom grey edge. Which H2 sections are grey is chosen per page.
  • Text and images inside a band never touch its edge: 30px to 60px of grey above the first block and below the last.
  • Only one grey is used: rgb(247, 247, 247).
  • Contact buttons at the end of the page are always on white.
  • Pages with no image, video or table (legal notices, policies, glossary) have no grey band, and neither do news, press and event items.
  • A page is not rejected for having, or not having, a band when it meets these points.
How to check
View mode, full page; R7 for the 30px to 60px and the 200px.
In global2
Container background colour on a top-level section, so that it spans the full window width. The grey is typed as rgb(247,247,247) (it is not one of the colour picker's swatches). A band section uses Padding - Top/Bottom: Small (30px); a list at the end of a band goes in its own grey section with No Padding, because the list adds 55px of its own.
Basis
Anion, 27 Sep: No need of BG color (Tariff Pass-Through Policy Notification, Glossary); Adjust BG color (eight news items).

C. Components

G10 Image beside its text (Text with Image) From review · numbers proposed

Pass when
  • An image placed beside its text (G11 decides which images) is in one Text with Image, image on the left.
  • The empty space between the image and the text is 60px or less: the component's fixed 40px plus half of any unused part of the image column (the image is centred in its column).
  • The image is at most 60px or a quarter of the text's height taller than the text, whichever is larger. Text height runs from the top of the first line's letters (a heading typed in the text included) to the bottom of the last line's letters.
  • Wrap is set when the text would otherwise be taller than the image by more than 120px or half the image's height, whichever is larger. With Wrap, the two points above do not apply.
  • Text with Image blocks that follow each other with only a title between them, or that sit in tabs of the same tab bar, use the same Image Width (%).
  • The image is never shown wider than its file (G3).
  • When these points conflict, they apply in this order: never wider than the file; the 60px space; the same width in a series; the heights. If the text needs Wrap but the file is wider than the width wanted for the image, Wrap is not used and the heights point is not counted.
How to check
View mode, R7. In the author: Image Width (%) in the Text with Image dialog, and the styles Image Position: Left and Text Wrapping: Wrap.
In global2
Text with Image, the component the review comments call image with text. Image Width (%) sets the width of the image column; Left places the image on the left; Wrap lets the text continue under the image, and the image then keeps its own file width, up to 48% of the block, so Wrap is used only when the file is no wider than the width wanted for the image. The component never enlarges an image: a small file in a wide column leaves empty space, so the width is chosen to fit the file.
Basis

Anion, 23 Sep: Lot of white space around the image – convert them into image with text; We see images were very big and used flex containers instead of flex conteianer use image with text component. G11 Where each image goes Proposed · question A5

Pass when

Images in a row or grid follow G3: equal Flex Container items, each image centred in its item. Every other image is placed by the first rule that applies:

  1. A diagram, chart or screenshot is shown as large as the page allows: at its file width, aligned left with the text of its section, or at the content width if its file is wider. It is not placed in a Text with Image.
  2. An image whose file is at least 900px wide fills the content width (enlarged at most 1.5 times).
  3. An image that GWI shows directly above, below or beside a paragraph of the same section, with no other block between them, sits beside that paragraph in a Text with Image, image on the left (G10).
  4. Any other image is shown at its file width, aligned left with the text of its section.

An image is never left alone in the middle of the page with wide empty space on both sides.

How to check
View mode. Right-click the image, Inspect: the browser shows the file's own width and the displayed width.
In global2
Image style Size: Expand to Fit Width (fills its column) and Display Position: Left; Text with Image for rule 3.
Basis
Anion, 28 Sep: image component - make image to full width to avoid space left and right (Japan Innovation Showcase). Anion, 23 Sep: Lot of white space around the image (AIoT).

G12 Videos From review · layout proposed

Pass when

  • The other item holds the title and paragraph that sit directly above, below or beside the video on GWI, with no other block between them: on the side where GWI puts them, or in GWI's reading order when GWI stacks them.
  • Where GWI has no text for the video, the other item holds the next video or stays empty, and the video keeps the same width.
How to check
View mode: the video and its text are side by side. Right-click the video, Inspect: the browser shows its width.
In global2
Flex Container with two Flex Container Items; Embed (style YouTube) in one of them.

G14 Buttons From review

End of page
  • A page ends with contact buttons where its GWI page does (question M2).
  • A page that ends with Contact Us for More Information and Request a Quote uses the Experience Fragment products-contact-block; one that ends with Sign up and Contact us uses signup-and-contact-experience-fragment. Any other ending (a single Request a Quote, an event's Register button, a supplier's website) stays as buttons on the page, with GWI's labels.
  • End-of-page buttons sit on white; each button of a pair is centred in its half of the row.
Other buttons
  • A button is in the same container as the sentence that introduces it, directly below it, with no other block between them. The button's own spacing then applies.
  • The buttons of one group are in one container and share one alignment. Two buttons side by side use Center in each Flex Container item.
  • A single Request a Quote button uses Fixed Minimum Width and Center.
Download buttons
  • Left-aligned, directly below their title or the line that introduces them, in the same container, with no other block between them; stacked when there are several.
  • Never on the same row as another button (a download button is 51px tall, a contact button 57px).
How to check
View mode: the background behind the end buttons, their position in the row, and what sits directly above each button. Right-click a button, Inspect, to see which container holds it.
In global2
Experience Fragment component; the section that holds it uses Padding - Top/Bottom: No Padding, because the fragment brings its own space. Button styles: Width (Fixed Minimum Width, Fit to Text) and Display Position (Center; none means left). Right is not used for buttons.
